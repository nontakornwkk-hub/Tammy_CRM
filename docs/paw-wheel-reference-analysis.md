# วงล้ออุ้งเท้า: วิเคราะห์ภาพอ้างอิงและการปรับหน้าเล่น

## โครงสร้างภาพ

ภาพอ้างอิงเน้นเกมหนึ่งหน้าบนมือถือ: ข้อมูลสมาชิกอยู่บนสุด ตามด้วยชื่อเกม แถบสะสมยอดซื้อ วงล้อ ปุ่มหมุน และปุ่มประกอบ การอ่านจึงไล่จาก “ฉันมีอะไร” → “ได้รับสิทธิ์อย่างไร” → “กดเล่นตรงไหน” โดยวงล้อเป็นจุดเด่นกลางหน้า

| องค์ประกอบ | สิ่งที่เห็นในภาพ | การนำมาใช้ |
| --- | --- | --- |
| ฉาก | ร้านสัตว์เลี้ยงไม้ แสงทอง หน้าต่างสีน้ำเงิน ชั้นสินค้าด้านขวา | สร้างฉากร้านเฉพาะเกม เก็บเป็น WebP ภายในโปรเจกต์ |
| ตัวละคร | ลูกหมาผ้าพันคอสีน้ำเงินซ้าย ลูกแมวผ้าพันคอเขียวขวา | แยกภาพโปร่งใสวางหน้าวงล้อ ให้หน้าตัวละครไม่ถูกวงล้อบัง |
| ข้อมูลสมาชิก | สามแคปซูลสีน้ำเงินเข้มสำหรับชื่อ แต้ม และสิทธิ์ | ใช้กริดสามช่อง ชื่อตัดด้วย ellipsis รูปใช้โปรไฟล์สมาชิกจริง ตัวเลขใช้ข้อมูลบัญชี |
| ชื่อเกม | ตัวอักษรทองบนขอบน้ำเงินพร้อมอุ้งเท้า | ใช้ข้อความจริงพร้อมเงาซ้อนและไอคอน ชื่อเปลี่ยนตามการตั้งค่าเกมได้ |
| ยอดซื้อ | แถบสีขาว ข้อมูลเกณฑ์และยอดที่ยังขาด พร้อม progress | ใช้เกณฑ์ร้านและยอดสะสมจริง ไม่ใส่ค่าจากภาพเป็นข้อมูลบัญชี |
| วงล้อ | ขอบทอง ไฟรอบวง ลูกศรอุ้งเท้า ช่องรางวัลนูน | Three.js เรขาคณิตจริง วัสดุโลหะและ reflection ไอคอนเหรียญ คูปอง กล่อง อาหารและขนมมีมิติ |
| การหมุน | ปุ่มสีน้ำเงินขนาดเด่นอยู่ใต้ฐาน | ปุ่มเดียวสำหรับเล่น ล็อกระหว่างรอคำตอบและหมุน แสดงโหมดฝึกชัดเจน |
| ปุ่มประกอบ | ปุ่มโค้งมนสีครีมขนาดเล็ก | กติกา ประวัติ และรางวัลของฉันอยู่แถวเดียวกัน โหมดฝึกของบัญชีจริงเปิดจากปุ่มใต้ปุ่มหมุน |

ฉากและตัวละครเป็นภาพประกอบ แต่ตัววงล้อ ลูกศร ฐาน ช่องรางวัล และการเคลื่อนที่เป็น WebGL จริง จำนวน/สี/รูป/ชื่อรางวัลของเกมจริงมาจากการตั้งค่า โหมดฝึกใช้ตัวอย่างแปดช่องที่แยกจากโอกาสออกรางวัลจริง

## การแก้ตำแหน่ง

- จำกัดพื้นที่เกมให้เป็นแนวตั้งและวางกลางพื้นที่สมาชิก โดยย่อได้ตามความกว้างหน้าจอ ไม่เปลี่ยนโครงสร้างหน้าสมาชิก
- วงล้อใช้กล้อง orthographic ในหน้าเล่น เพื่อให้ขนาดสัมพันธ์กับความกว้างคงที่ ไม่เล็กลงจากการพยายามใส่ฉากร้านทั้งหมดในกล้อง
- ฉากภาพและตัวละครแยกจาก canvas; ชั้นตัวละครไม่รับ pointer event จึงไม่บังการกดปุ่ม
- หน้าต่างผลหมุน กติกา ประวัติ และรางวัลใช้ native dialog ใน top layer ผ่าน portal ไปที่ document.body พร้อม inset:0 และ margin:auto แก้อาการติดมุมซ้ายบนและหลุดกรอบโทรศัพท์
- จำกัดความกว้างและความสูง dialog ตาม viewport เนื้อหายาวเลื่อนภายในได้ Escape ปิดได้และคืน focus ไปยังปุ่มที่เปิด
- หยุด polling รางวัลเมื่อปิดหน้าต่าง และจำรอบที่ animation จบแล้ว เพื่อไม่แสดงผลรอบเดิมซ้ำเมื่อฉากถูกสร้างใหม่

## ขอบเขตที่คงเดิมตามคำสั่ง

แถบเมนูสมาชิกด้านล่างทั้งห้ารายการไม่แก้ markup, CSS, รูปไอคอน, สี, ขนาด หรือตำแหน่ง ไฟล์ CustomerNavigation, CustomerNavIcon และ customer-navigation.css ไม่มี diff ในงานนี้ CSS ใหม่จำกัดขอบเขตเฉพาะ .paw-game--cinematic และ .paw-dialog

## การเล่นจริง

MemberGameHub ส่งคำขอไป /api/line/member/games ด้วย token สมาชิกและ request UUID ผลรางวัลที่ API ยืนยันเป็นตัวกำหนดช่องหยุด ส่วน animation เป็นการแสดงผลตามคำตอบนั้น การคำนวณสิทธิ์ หักสต็อก เพิ่มแต้ม ออกรางวัล และ QR ยังใช้ระบบฐานข้อมูลเดิม

สิทธิ์จากยอดซื้อสะสมยังบันทึกตอนให้แต้ม สิทธิ์ที่แอดมินให้เพื่อทดสอบยังเป็นสิทธิ์ชั่วคราว โดยการหมุนด้วยสิทธิ์ทดสอบให้รางวัลจริงและตัดสต็อกจริงตามคำสั่งก่อนหน้า ส่วน “ฝึกเล่น” ไม่มีการให้รางวัลจริง

## หลักฐานการตรวจ

- TypeScript และ production build ผ่าน
- Browser ตรวจหน้า /customer/games-preview ที่ความกว้าง 360, 390, 430 และ 1280 พิกเซล: ไม่มี horizontal overflow
- เปิด dialog กติกา ประวัติ และรางวัล; ตรวจตำแหน่งกลาง viewport และ Escape/focus restoration
- หมุนโหมดฝึกครบหนึ่งรอบ: ปุ่มถูกล็อกขณะหมุน เปิดผลรางวัล และกลับไปเล่นต่อได้ ไม่มี page error
- จำลอง WebGL context loss ระหว่างหมุน: fallback เปิดผลได้ ปุ่มกลับมาใช้งานได้ และหน้าต่างไม่เปิดซ้ำหลังปิด
- tests/game-platform.mjs ผ่าน: เกณฑ์ยอดซื้อ/ยอดยกไป การหักสิทธิ์/คำขอซ้ำ แต้มจริง สต็อก คูปอง/วันหมดอายุ/เงื่อนไขรับ สิทธิ์ทดสอบโดยไม่สร้าง wallet/ticket ถาวร และการกันเข้าถึงข้ามบัญชี

Browser verification ใช้โหมดฝึกที่ไม่มีการเปลี่ยนข้อมูลสมาชิกจริง ส่วนการรับรางวัลจริงตรวจด้วยฐานข้อมูลทดสอบแบบ isolated ที่ใช้ migrations ของระบบเดียวกัน
